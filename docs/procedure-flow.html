02

How a click becomes an authorised write

Access is resolved once per request, in one function, and every department context is built on that answer. This is the structural fix for the class of bug where the button a screen offers and the write path behind it disagree.

Dead capability

quality.documents.share is grantable on the Access screen and grants nothing. The key builder ix:qshare, the qualityShareLinks collection and the reserved /q route prefix all exist; no code reads or writes any of them. Two more follow the same pattern: s:<id>:activityLog and ix:stoken are declared and never touched.

04

Where everything lands

The ownership tree is the key tree. That single decision is what makes cascading deletion equal to prefix deletion — Redis has no ON DELETE CASCADE, so the hierarchy has to carry the guarantee.

05

How a change reaches every open screen

Three pieces with a strict division of labour: the stream is truth, pub/sub is only a doorbell, and SSE is the wire. Confusing any two of them is how a reconnect silently drops events.

06

Who gets told, and who doesn't

A notification is not an event. The event log is machinery — no words, forgotten once clients catch up. A notification is addressed to a person, says something in a sentence, and persists until read. Five producers exist. The gaps are where an ERP normally does its work.

07

Where the machinery is exposed

Critical · data loss

The weekly orphan sweep mixes two key-addressing conventions in one function: it repairs through the prefixed builders and reaps through bare string literals. Run once with a key prefix set — which the project's own integration bootstrap sets unconditionally — it reads empty registries, classifies every real user and studio subtree as orphaned, and deletes them by prefix.
