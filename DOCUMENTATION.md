# Studio Documentation — progress & reference

**This file is the source of truth for the in-studio Documentation section.** When asked to update the documentation, use this file as the reference so you only **add/modify** the affected articles — never rewrite the whole guide.

- **Live at:** Studio → **Documentation** (`/studio/documentation`), access-controlled node `documentation` (+ `documentation-settings`).
- **Content module:** `src/lib/documentation.js` — `DOC_SECTIONS` (array of sections → `articles` → `body` blocks) and `imageSlots()`.
- **Screenshots:** admins upload at **Documentation → Settings**, tagging each image by **location (slot)** + description. New `{ type: "image", slot }` blocks auto-appear in that dropdown. Stored in the `docImages` collection.
- **Renderer:** `src/components/studio/DocumentationGuide.js` (guide) + `DocumentationSettings.js` (image manager).

## Block types (an article `body` is an ordered list)
| type | shape | renders as |
|---|---|---|
| `p` | `{ text }` | paragraph (supports `**bold**`) |
| `h` | `{ text }` | subheading inside an article |
| `steps` | `{ items: [text] }` | numbered steps (supports `**bold**`) |
| `table` | `{ headers: [], rows: [[]] }` | generic reference table |
| `fields` | `{ items: [{ name, required, auto, desc }] }` | required-vs-automatic field table |
| `note` | `{ text }` | highlighted callout |
| `image` | `{ slot, label }` | screenshot slot (filled via Settings; `slot` must be globally unique) |

## How to update the documentation
1. Read this file to find the section/article `key` that owns the behavior.
2. Edit that article's `body` in `src/lib/documentation.js` (add/modify blocks). To add a screenshot spot, add `{ type: "image", slot: "unique-slot", label: "…" }`.
3. Add a line to **Change log** below.
4. Verify locally, then `vercel deploy --prod --yes`.
5. Regenerate this file's index if sections/articles changed.

- 2026-08-12 — **One-time-code delivery is now bounded and retried** (`lib/email.js`, `lib/identity.js`). `sendEmail` made a single un-timed `fetch` with no retry, so a hung Resend could hold a signup open until Vercel killed the function (~300s), and a transient **429/503 permanently locked a person out of their own signup**. It now retries up to 3 attempts with 300ms/900ms backoff, honours Resend's `Retry-After`, times each attempt out at 4s and caps the whole call at a **10s budget**. Refusals are NOT retried — a 422 (bad address) or 401 (bad key) will not change on a second try, so the caller is not made to wait for it. `sendEmail` still never throws and still returns `emailSent` for the signup/login/OTP forms, now with an `attempts` count that is logged on failure. Deliberately NOT moved to a background queue: every message the product sends is a code someone is actively waiting for, so deferring it would not shorten their wait and would throw away the "we couldn't send the code" signal three forms depend on. Verified 11/11 against a stubbed provider (no mail sent): retry-on-transient, no-retry-on-refusal, abort-on-hang, `Retry-After` honoured, kill-switch intact. Docs: no article change (backend/infra).
- 2026-08-12 — **Live updates across every studio board, and atomic writes underneath them.** Two changes, no database-structure change. (1) **Atomic writes:** a collection is one Redis key holding a whole array, so the old "read it, change a row, write it back" silently lost data whenever two overlapped — measured at **40 concurrent appends leaving 1 survivor**. Every read-modify-write now goes through `editArr`/`editJSON` in `data/store.js`, a compare-and-set run inside Redis (Lua + `redis.sha1hex`), costing the same one read + one write as the unsafe version. This fixes: a double-approve creating **two collaborator rows** for one person, **lost permission grants** when two admins edited access at once, the **OTP attempt limit being multiplied** by a burst of parallel guesses, dropped sessions invisible to "sign out everywhere", and lost registry rows that **permanently burned a studio slug**. Replaced the old advisory lock (5 round trips, and it failed *open* on timeout); removed `writeCol()`, the last blind-write path. (2) **Live updates:** a capped Redis Stream per studio at `s:<StudioID>:events` (a new key — no stored document changed, and it cascades with the studio), written by `addRow`/`updateRow`/`deleteRow` plus people/grants/join-requests. `GET /api/studios/[slug]/events?since=<cursor>` gates **per event** against the same `canViewSection()` the sections use, so no-one learns a section they can't read is busy. `useLiveUpdates` reuses each board's existing `load()`; all 11 boards now refresh themselves within ~30s, and hidden tabs poll nothing. Verified 31/31 (12 offline concurrency, 10 live atomicity, 9 live event-log) against production Redis 8.6.2. Docs: no article change (backend/infra).
